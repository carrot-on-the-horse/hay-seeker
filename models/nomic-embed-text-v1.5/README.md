# Offline Nomic Embed ONNX bundle

This Apache-2.0 model profile is the license-permissive default for exercising
Hay's complete offline dense path. The model remains a caller-provisioned
artifact and Hay never downloads it at runtime.

The checked-in manifest pins the official `nomic-ai/nomic-embed-text-v1.5`
revision `1ef9b3e52d22d5957a7ca765fd83c68c3bffa91b`, its published quantized ONNX
graph, tokenizer, and both SHA-256 digests. Download those two files from that
exact revision, copy `bundle.example.json` to `bundle.json`, and set
`HAY_LOCAL_MODEL_DIR` to the bundle directory.

The adapter implements the model card's retrieval contract exactly:

- documents use the `search_document: ` prefix;
- queries use the `search_query: ` prefix;
- padded token states are mean pooled with the attention mask;
- the 768-dimensional pooled vector is layer-normalized;
- MRL truncation selects the leading 256 or 768 dimensions;
- the selected vector is L2-normalized.

The official dynamic quantized graph declares `core_ml_compatible: false`.
Apple's NeuralNetwork conversion worked for short inputs but took more than
three minutes on the first real 128-document code batch; CPU completed the
same full repository in 49 seconds and encoded short queries in 5–6 ms. The
loader therefore skips Core ML for this exact graph. Other bundle profiles,
including the EmbeddingGemma contract, retain the Core ML-first behavior.

DuckDB stores 256 dimensions with per-vector int8 scale and offset.
Elasticsearch stores 768 dimensions with BBQ. Both are generated by this same
checksum-pinned graph and tokenizer.

Validate the bundle and measure local query latency:

```bash
HAY_LOCAL_MODEL_DIR=/absolute/path/to/nomic-bundle \
  cargo run --release -p cast-embeddings --example local_onnx_smoke
```
